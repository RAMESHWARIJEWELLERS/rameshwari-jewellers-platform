2.2 Chatbot credentials — LOCKED

RuleDetail
Where secrets liveServer-side configuration only — wp-config.php constants or environment configuration. API keys, secrets and equivalent private credentials are never written to the options table.
What the group storesProvider selection and non-secret configuration. Nothing more.
Admin displayA configured / not configured indicator derived from whether the constant is defined and non-empty. The secret value is never rendered, never masked-but-present in the HTML, never sent to the browser at all.
Never appears inREST responses · exports · activity-log diffs (changed flag only) · debug output · ordinary admin page HTML.
No second storeNo custom credential table, no encrypted credential store, no parallel secret mechanism. This is the same rule the locked architecture already applies to rj_auth_providers and rj_notifications — three subsystems, one consistent pattern.
PortabilityConstants are the one credential mechanism that works identically on InfinityFree, Hostinger, cPanel and managed WordPress. A host move carries the constant, not a database row.

5 · Final architecture statement

Canonical statement — replaces the widget-count debate everywhere

Rameshwari Jewellers uses an Elementor Free-first integration architecture. Elementor Free/Core is the compatibility baseline. Elementor Pro may enhance presentation capabilities but is never a dependency for core business functionality. RJ Plugin owns business data and business logic. Shared renderers and services are exposed through native builder capabilities, shortcodes, theme components and RJ Free-compatible widgets as appropriate. Optional Pro dynamic tags and advanced features sit above this baseline.
